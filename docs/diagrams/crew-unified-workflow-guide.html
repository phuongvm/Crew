01. How You Use It: Adaptive Dual-Entry Intake Flow

Standalone SVG: crew-unified-intake-flow.svg

PATTERN A · CHAT FIRST, DISPATCH SECOND

Explore in Chat → /crew-no-spec

  • Chat naturally to investigate a repo, debug an issue, or brainstorm a product idea.
  • The agent uses Graphify MCP + diagnosing-bugs / grilling and writes openspec/workspace/explorations/*.md.
  • When ready to execute without formal spec ceremony, type /crew-no-spec implement this — Mode 1 attaches the Exploration Doc to Inputs: and opens the card in Turn 1.

PATTERN B · DIRECT SLASH DISCOVERY

Start Directly with /crew-no-spec

  • Type /crew-no-spec <problem or feature> cold.
  • If the ask needs root-cause proof or design decisions, Mode 2 automatically triggers the 4-Step Guided Discovery Loop while keeping the 30-min intake window open.
  • Once you confirm the frontier round (go), the card dispatches immediately.

PATTERN C · FULL SPEC GOVERNANCE

When to Use /crew Instead

  • Use /crew <ask> when the change alters canonical system contracts that must live in openspec/specs/.
  • If an Exploration Doc already exists from chat, /crew skips Phase 1 and goes straight to openspec-propose.

02. How It Functions: 4-Role Swimlane Choreography

Standalone SVG: crew-multi-agent-swimlane.svg

LANE 1 & 2 · INTAKE & DISCOVERY

When Agent Asks vs. Acts

  • Never asks for codebase facts: Uses Graphify MCP + diagnosing-bugs to find facts and reproduce bugs empirically (<5s probe).
  • Asks only unsettled design decisions: Uses Matt's grilling frontier rounds (❓ Q1 ➡️ Recommended) and clarify.

LANE 3 · WORKER (@CODER / @DESIGNER)

TDD at Public Seams & Prototypes

  • Reads the Exploration Doc from Inputs: and checks sibling callers via mcp__graphify__get_neighbors.
  • Isolates branch work via crew_worktree_create (Zero-Checkout) and executes Red→Green tdd at the public seam.

LANE 4 · VERIFIER (@REVIEWER)

3D Audit & Anti-Tautology

  • Re-runs crew_verdict in a clean BoundedRunner environment (rc=0).
  • Audits Completeness/Correctness/Coherence against Inputs: and rejects tautological tests via crew_request_changes.

03. How It Is Designed: Four-Pillar Skill Architecture (CREW-INV-8)

Standalone SVG: crew-four-pillar-architecture.svg

DEEP MODULE DESIGN

Narrow Interface, Rich Behavior

  • Your interface is just two commands: /crew-no-spec and /crew.
  • Behind that narrow seam sit 41 sub-skills and MCP tools, automatically routed by task nature without prompt boilerplate.

DURABLE EXPLORATION SPINE

Exploration Document as Bridge

  • Every non-trivial investigation writes <project>/openspec/workspace/explorations/YYYY-MM-DD-<topic>-exploration.md.
  • Both /crew-no-spec and /crew pass that file directly into the card's Inputs: line.

CREW-INV-8 PROTECTION

Survives Upstream Merges

  • 12 static anchors in daily-sync-watchdog.ps1 guard all 5 SKILL.md files against regression during daily 04:40 ICT upstream syncs.
